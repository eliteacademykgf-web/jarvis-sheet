# jarvis-sheet

Данные для таблицы сквозной аналитики: CRM-метрики за день из AmoCRM
и статистика объявлений по дням из Meta Marketing API.
Пишет сырые данные в Google Sheets (листы `meta_daily` и `crm_daily`) и собирает из них лист «Сквозная аналитика <Месяц>». Telegram здесь нет.

## Файлы

- `config.py`: переменные окружения (`AMO_DOMAIN`, `AMO_TOKEN`, `META_TOKEN`, `AD_ACCOUNT_ID`, `SPREADSHEET_ID`, `GOOGLE_SERVICE_ACCOUNT_JSON`).
- `amo_client.py`: запросы к AmoCRM. Перенесено из `jarvis-amo/main.py` без изменения поведения.
- `metrics.py`: `compute_daily_metrics(date, pipeline_id)`, одна сводка CRM на день без разбивки по объявлениям.
- `build_daily_source.py`: `build_meta_rows(date)` (строка на объявление, Meta) и `build_crm_row(date)` (одна сводка CRM на день). Не склеиваются: склейка на уровне таблицы.
- `sheets_client.py`: подключение к Google Sheets и upsert на листы `meta_daily` / `crm_daily`.
- `sheet_builder.py`: `rebuild_month_sheet(year, month)`, пересборка листа месяца одним `batchUpdate`.
- `write_to_sheets.py`: запись дня или диапазона дней (по умолчанию вчера) в таблицу и пересборка листа месяца.
- `verify.py`: один день (по умолчанию вчера): Meta по объявлениям и CRM одной сводкой, друг под другом. С `--month` выводит суммы за прошлый календарный месяц для сверки с ботом.
- `meta_client.py`: `get_daily_ad_stats(ad_account_id, date, access_token)`, строки объявление × день.
- `verify_meta.py`: последние 7 полных дней из Meta для ручной сверки с Ads Manager.

## Запуск локально

```bash
cd jarvis-sheet
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env    # заполнить AMO_* и META_TOKEN / AD_ACCOUNT_ID
python verify.py              # вчера: Meta по объявлениям + CRM за день
python verify.py 2026-09-20   # конкретный день
python verify.py --month      # сверка месяца с ботом
python verify_meta.py
python write_to_sheets.py              # вчера → Google Sheets
python write_to_sheets.py 2026-09-20   # конкретный день
python write_to_sheets.py 2026-09-01 2026-09-23   # дозаливка диапазона
python sheet_builder.py 2026-09        # только пересобрать лист месяца
```

Можно без `.env`: переменные окружения тоже подхватываются
(`AMO_DOMAIN=... AMO_TOKEN=... python verify.py`).

## Как считаются показатели

- Этапы накопительные («дошёл до этапа или дальше») по `sort` статусов воронки.
  Открытые лиды оцениваются по текущему статусу. У закрытых (142/143) берётся
  максимум по истории `lead_status_changed`. 143 при этом не учитывается,
  142 считается дальше всех этапов.
- Когорта: лиды, созданные в этот день в «Отделе продаж», после `dedup_leads`.
- Продажи и выручка: события перехода в 142 или «получена предоплата».
  Продажа засчитывается один раз, в день ПЕРВОГО такого события за всю историю
  сделки (предоплата 3-го и 142 20-го — продажа 3-го). Бот считает иначе:
  у него такая сделка — продажа в обоих периодах. Выручка — сумма `price`.
- Сумма этапов по дням может быть чуть больше расчёта за месяц одним
  периодом: дедупликация по контакту/телефону работает внутри дня.

## Нагрузка на API

История переходов запрашивается через `/events` с `filter[entity_id]`,
по 10 лидов за запрос (больше AmoCRM не принимает). При ~130 сделках в день
это ~13 запросов на историю плюс лиды, контакты и события продаж.

## Meta

- Graph API v26.0. Запрос `/act_{id}/insights` с `level=ad`, `time_increment=1`,
  пагинация по `paging.next` до конца.
- Дни в часовом поясе рекламного аккаунта (сейчас Europe/Moscow, UTC+3),
  а CRM считает по Бишкеку (UTC+6).
- Токен передаётся заголовком `Authorization` и в URL не попадает. Все тексты
  ошибок и логов маскируются (`access_token=***`).
- Ошибка Meta поднимает `MetaAPIError` (message, code, HTTP-статус).
- `dm_leads` и `site_leads` хранятся раздельно (открытый вопрос ТЗ №5).
- Объявления без активности Meta не возвращает, нулевых строк нет.

## Google Sheets

- Сервисный аккаунт, JSON-ключ по пути `GOOGLE_SERVICE_ACCOUNT_JSON`. Ключ хранить
  вне репозитория. Аккаунт должен быть редактором таблицы, иначе
  `SheetsAccessError` («Нет доступа к таблице …»).
- Скрипт трогает только свои листы `meta_daily` и `crm_daily`. Если листа нет,
  он создаётся с заголовками. Существующий лист не меняется, кроме строк данных.
  Остальные листы не удаляются и не меняются.
- Upsert по ключу: `(date, ad_id)` для `meta_daily`, `date` для `crm_daily`.
  Повторный запуск за тот же день обновляет строки на месте.
- Одно чтение листа и один `batch_update` на лист. Полный прогон за день
  вместе с пересборкой листа месяца — 13 запросов к Google API.
- Запись `RAW`: `date` и `ad_id` лежат текстом (иначе Sheets округлит 18-значный
  `ad_id` и переведёт дату в число), числа — числами. В формулах дату
  можно получить через `DATEVALUE`.

## Лист «Сквозная аналитика <Месяц>»

Один лист на календарный месяц. Если его нет, создаётся. Каждый прогон
пересобирает лист целиком из `meta_daily`, `crm_daily` и `ads_manual`.
Ручные правки на самом листе затираются, поэтому править нужно `ads_manual`.

- Строка 1 — «В общем за месяц» (сумма итоговых строк дней, H/I/L/N/O/R —
  формулы от сумм). Строка 2 — шапка. Ниже блоки дней, новые сверху.
- Блок дня: строка на каждое объявление из Meta (по убыванию расхода).
  A (дата) и K–R (CRM) объединены по высоте блока: CRM — одно число на день.
  Строка «В общем» — итог дня. CPM и CTR итога взвешенные: F/G*1000 и клики/показы.
- CTR из Meta приходит в процентах (0.577 = 0,577%), на лист пишется / 100.
- Скрытые колонки: S — `ad_id`, T — клики (нужны для CTR итогов).
- D (кодовое слово) и E (статус) берутся из `ads_manual` по `ad_id`. Новые
  `ad_id` дописываются туда с пустыми `code_word` и `status`. Существующие
  строки `ads_manual` скрипт не меняет.
- Всё пишется одним `spreadsheets.batchUpdate`, запрос атомарный: при ошибке
  лист остаётся как был.
- Если формулы других листов ссылаются на лист месяца, пересборка
  отказывается (строки сдвигаются, ссылки бы сломались).
- Формулы без разделителей аргументов (`+`, `/`, `IFERROR` с одним
  аргументом): у таблицы локаль ru_RU.
